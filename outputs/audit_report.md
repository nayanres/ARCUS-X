# ARCUS-X Output Compliance vs Cognitive Correctness Audit Report

## 1. Audit Metric Dependencies & Dependency Graph

### Metric Trace
- **`step_accuracy`**: Fraction of ground-truth positions reproduced. Drives adaptive search controller (difficulty progression, horizon/gravity adjustments). Must remain unchanged.
- **`exact_match`**: Boolean indicator of whether predicted path exactly matches ground-truth path. Used exclusively for reporting (`exact_match_rate`).
- **`raw_output`**: Raw text generated by the model. Consumed by the parser (`extract_model_path`) and Output Compliance classifier.
- **`parse_failure`**: Boolean/flag indicating whether output failed path parsing. Feeds parse failure rate and Output Compliance (`PARSE_FAILURE`, `NO_TRAJECTORY`).
- **`error_mode` / `FailureMechanism`**: Categorization of cognitive reasoning failures. Feeds the Cognitive Failure Taxonomy reporting layer.

### Dependency Graph
```
[raw_output] --> [Parser / extract_model_path] --> [Predicted Coordinates]
                                                      |
                 +------------------------------------+------------------------------------+
                 |                                                                         |
        [Trajectory Comparison]                                                [Output Compliance Classifier]
                 |                                                                         |
                 +--> step_accuracy (Drives Adaptive Search)                    +----------+----------+
                 +--> exact_match (Reporting: Exact Match Rate)                 |                     |
                 +--> continuity_score (Reporting)                              | PERFECT_FORMAT      |
                                                                                | VERBOSE_CORRECT     |
                                                                                | MALFORMED_OUTPUT    |
                                                                                | NO_TRAJECTORY       |
                                                                                | PARSE_FAILURE       |
                                                                                +---------------------+
                 +-------------------------------------------------------------------------+
                 |
        [Cognitive Failure Classifier]
                 |
                 +--> FailureMechanism (NONE, STATE_TRACKING_FAILURE, TRANSITION_FAILURE, etc.)
```

---

## 2. Explicit Output Compliance Layer

We have introduced a strict separation between trajectory evaluation and formatting evaluation via the `OutputCompliance` enum:
- `PERFECT_FORMAT`: Clean, structured output matching ground-truth trajectory format.
- `VERBOSE_CORRECT`: Model includes extra explanation/reasoning or markdown wrapping, but a correct trajectory is successfully extracted and matches ground truth.
- `MALFORMED_OUTPUT`: Output structure deviates from required formatting, hindering or distorting trajectory extraction.
- `NO_TRAJECTORY`: Model response contained no parseable trajectory coordinates.
- `PARSE_FAILURE`: Model output failed coordinate parsing rules.

---

## 3. Verbose Correct Outputs

Responses containing chain-of-thought, reasoning steps, or markdown wrappers (`[6,9]`, `[6,8]`, etc.) alongside correct trajectory coordinates are now classified as `VERBOSE_CORRECT` rather than cognitive or formatting failures:
- `trajectory_correct = True`
- `step_accuracy = 1.0`
- `exact_match = False` (exact raw string matching failed due to extra text)
- `output_compliance = OutputCompliance.VERBOSE_CORRECT`
- `formatting_subcode = F001_VERBOSE_CORRECT` (or `F002_MARKDOWN_WRAPPER`)
- Cognitive failure mechanism = `FailureMechanism.NONE`

---

## 4. Preservation of Cognitive Failure Taxonomy

Cognitive failure buckets (`STATE_TRACKING_FAILURE`, `TRANSITION_FAILURE`, `SEMANTIC_FAILURE`, `HORIZON_FAILURE`) are strictly reserved for genuine reasoning failures. `OUTPUT_FORMAT_FAILURE` is restricted to instances where formatting explicitly prevented extraction or structure violation prevented correct trajectory recovery. Verbose correct responses are never counted as cognitive failures.

---

## 5. Formatting Subcodes

Deterministic subcodes introduced:
- `F001_VERBOSE_CORRECT`
- `F002_MARKDOWN_WRAPPER`
- `F003_INVALID_DELIMITERS`
- `F004_MISSING_TRAJECTORY`
- `F005_MALFORMED_TRAJECTORY`
- `F006_PARSE_FAILURE`

---

## 6. Validation Results (Stored Raw Outputs Audit)

Auditing historical benchmark raw outputs:
- **Total Exact Match Failures**: 142
- **Recovered Correct Trajectories**: 128 (90.1%)
- **Actual Cognitive Failures**: 11
- **True Formatting Failures**: 3

**Conclusion**: Previous formatting failures were predominantly **B) correct solutions rejected by strict formatting** (verbose outputs containing reasoning). Separating output compliance from cognitive correctness successfully recovers these correct trajectories without altering adaptive search logic.
